Objective

Show how a multi-agent system can diagnose and fix a problem that no single platform can see on its own. Two separate teams (Satellite and AAP) each made a valid change to the infrastructure. Each change looks fine in isolation. But together, they create a hidden performance problem that only appears under load — and neither team's monitoring catches it.

Scenario: A payment service runs on two RHEL servers behind a load balancer. Two things happen:

  • The Satellite team applies a stricter crypto policy (FUTURE:CLASSICAL-COMPAT) to both servers — this raises the minimum TLS key size.
  • The AAP team deploys a TLS compliance fix on one server only — this installs a 6144-bit RSA certificate, which is now extremely expensive to handshake under the stricter policy.
  • Result: one server becomes 20x slower on TLS handshakes. Customers see intermittent slowness (fast when the load balancer routes to the healthy server, slow when it routes to the affected one). Health checks still pass. Error rates are 0%. No alerts fire.

The multi-agent system investigates both platforms simultaneously, correlates the two changes, identifies the root cause, writes a remediation playbook, executes it via AAP, and produces an RCA report — all autonomously.

  2. 2
    Update Security Policy (AAP)

    Done from the AAP portal: Templates → launch IntelliMesh Security Compliance (playbook 02-inject-compliance.yml, limit patched). This is the "TLS compliance fix" that — unseen by Satellite — deploys the oversized cert on Node 2 and causes the slowdown.

    Open AAP Portal ↗
  3. 3
    Observe the Impact

    Both platforms still report green — the slowdown only shows up in TLS handshake latency on the dashboard.

    Open Grafana Dashboard ↗
  4. 4
    Let the Multi-Agent System Investigate

    Switch to the Agent Workflow tab and trigger the multi-agent workflow. It correlates the Satellite and AAP change history via MCP, identifies the root cause, and suggests a remediation — closing the gap neither platform could see on its own.

  5. 5
    Revert to Healthy Baseline

    Runs 00-cleanup-satellite-tasks.yml (clears stale/stopped Satellite job leftovers) then 00-setup-backends.yml — restores the RSA-4096 cert, correct SSL params, and resets the crypto policy to DEFAULT. Cleans up the environment so it's ready for the next demo run.
