Scenario

Two independent teams — Satellite (OS hardening) and AAP (TLS compliance) — each apply changes to the same RHEL infrastructure. Both report success. Neither detects that their combined actions degrade TLS performance by 20x on one node.

Objective

Demonstrate how a multi-agent system can investigate across platforms via MCP, correlate the timeline of changes, identify the root cause, and recommend remediation — closing the visibility gap that no single platform can see on its own.

Satellite Team Enforces

OS-level security hardening applied to all servers:

  • Stricter crypto policy (FUTURE:CLASSICAL-COMPAT)
  • Restricts allowed ciphers and protocols
  • Applied to both nodes equally
  • Reports: "Policy applied successfully"

AAP Team Enforces

TLS compliance fix applied to one server:

  • Deploys 6144-bit RSA certificate
  • Disables SSL session caching
  • Applied to Node 2 only
  • Reports: "Job completed successfully"

Multi-Agent System

The multi-agent system sees what individual platforms cannot:

  • Orchestrator dispatches specialized agents
  • Satellite Investigator queries policy changes via API
  • AAP Investigator queries job history via MCP
  • Cross-correlates timelines across both platforms
  • Identifies the root cause and suggests remediation

The Result

Both platforms report green. But Node 2 is now 20x slower on every TLS handshake. Customers experience intermittent slowness. No alerts fire. No errors logged.
